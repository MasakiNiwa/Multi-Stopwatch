## できたこと

初期基盤の機能契約（model.js / storage.js / schema v1）を保ったまま、仮UIを初版の完成形へ作り直した。
実ブラウザでの検証も実施し、結果はdocs/acceptance.mdに追記した。実機（Android/iOS）とGitHub Pages配信は未確認。

### 直した問題

- 追加してからキャンセルすると空の計測が残った。追加は下書きを編集画面で確定してから保存する方式に変更
- 操作のたびに全カードを作り直していたため、フォーカス・スクロール位置が失われた。id単位の差分更新に変更
- 計測中のカードで編集画面を開くと、累積値（表示より短い時間）が出ていた。表示中の時間を初期値にし、**変更した時だけ**反映する
- 経過時間の修正が「秒だけの入力」だった。時/分/秒に分割
- 経過時間を0に戻せないリセットボタンが押せる状態だった。0のときは無効化
- 読めない保存データのとき、案内文が指す「バックアップを保存」が閉じた折りたたみの中にあった。自動で開く
- `confirm()`による確認を、アプリ内ダイアログへ変更（インストール後の表示差とデザイン統一のため）

### UI/UXの変更

- スマホ前提の1カラム。カードは「名前 → 状態 → 時間 → 目標 → 操作」の順で、開始/停止を最大の操作にした
- 旧Flutter版の時間表示（`00h00m00s`の単位付き）を引き継ぎ、秒を控えめにして時・分を読み取りやすくした
- 計測中のカードは枠線・淡い色・点滅ドットで区別。合計と計測中の件数は上部に固定表示
- 色選択をセレクトボックスから見本付きの選択肢へ。並べ替えはカード右上、破壊的操作は下段に分離
- 空状態、削除・リセット・復元の確認、操作結果の通知（8秒で消える）を追加
- ダークテーマ、`prefers-reduced-motion`、44px以上のタップ領域、全操作のキーボード対応とラベル付け

### 構造

- `public/src/ui.js` を追加し、描画とダイアログをapp.jsから分離（app.jsは状態・保存・イベントのみ）
- `model.js` に `setElapsed` `total` `running` `parts` `speak` `progress` を追加。表示と集計も純粋関数側でテストできる
- `sw.js` はVERSIONをv0.2.0へ。ui.jsを事前キャッシュに追加し、範囲内の未知パスは本体へフォールバック
- HTML/CSSは1行圧縮をやめて改行した。差分レビューと今後の調整のため。圧縮が望ましければ戻す

### 判断が要る点（ChatGPTに見てほしい）

1. **長い名前・メモの切り詰め**（3行/4行）。全文はカードに出ないが`title`と編集画面で読める。この割り切りでよいか
2. **削除ボタンをカード上に常設**した。誤操作は確認ダイアログで防いでいるが、編集画面へ隠す案もある
3. **HTML/CSSの整形**（上記）。初期基盤の書式と方針が違うため、リポジトリの方針として決めてほしい
4. **色は4色のまま**にした。旧版は8色だが、schema v1の`COLORS`を変えずに済ませている。増やすなら移行の要否を含めて次段階で
5. **平均時間・固定7タブ・履歴は未着手**。design.mdの拡張順序どおり、初版の範囲を広げないため見送った

## ChatGPTレビュー（2026-09-13）

計測・保存・PWAの実装と10テストを確認し、公開を止める機能上の問題は見つからなかった。Claudeが挙げた判断事項は次の方針とする。

1. 長い名前・メモはカード内で切り詰め、編集画面で全文を読む現在の方式を採用。
2. 削除はカード内に残す。視覚的な優先度を下げ、確認ダイアログで誤操作を防ぐ。
3. HTML/CSSは読みやすい整形済み形式を採用。
4. 初版は4色。実使用後に必要性を判断。
5. 平均時間・固定7タブ・履歴は初回公開後の候補。

ユーザーの「少し一昔前に見える」という評価を受け、ChatGPTがv0.3のビジュアルを再設計した。外部UIライブラリは使わない。規模に対してビルドやオフライン更新が複雑になるためで、プロダクトコードは依存なしを維持する。テスト用途にPlaywrightを追加し、GitHub Actionsで変更後のライト/ダーク・スマホ/PC画面、サブパス、再読込、オフライン起動を検証する。


## ユーザー実機レビューと次の担当（2026-09-13）

次の担当：**Claude（コーダー兼デザイナー）**。実装後、節目でChatGPTが技術・品質・UXをレビューする。

### 実機で確認できたこと

GitHub Pages公開版をユーザーが実機で起動・操作できた。以降は公開版を自分で使いながら改善する。

### 次の要望

1. 元Flutter版の核である「多数のストップウォッチを、煩雑に見せず一画面に多く収める」を取り戻す。
2. 多数あっても目的のストップウォッチをすぐ見つけ、開始・停止できる。
3. 並べ替えを日常的に使いやすくする。現在の上下ボタン以外にドラッグ操作等も検討するが、キーボード操作は失わない。
4. テーマを「端末に合わせる／ライト／ダーク」から明示的に選べるようにし、選択を端末内へ保存する。
5. v0.3の現代的な雰囲気は保ちつつ、カードの高さ・余白・操作数を見直して一覧性を高める。

### Claudeの実装課題

- モバイルを主対象に、コンパクト表示を設計する。単なる縮小ではなく、名前・時間・状態・主操作の優先順位を守る。
- 通常表示とコンパクト表示の切替が必要か、常時コンパクトで十分かを実画面で比較して決める。
- 編集・削除・リセット・並べ替えなど低頻度操作を、主操作を邪魔しない場所へ整理する。
- 10件以上を登録した状態、長い名前、計測中が複数ある状態で確認する。
- テーマ選択は初期値をsystemとし、保存値はUI設定用の別キーで管理する。ストップウォッチschema v1を変更しない。
- manifestのtheme colorと実画面の配色が選択テーマと大きく食い違わないよう対応する。
- Service Worker対象を変えたらVERSIONを更新する。
- 実装・スクリーンショット・検証結果をPRにまとめ、ChatGPTレビュー待ちにする。

### 受け入れ条件

- 390×844でストップウォッチ4件以上の名前・時間・開始停止が、過度なスクロールなしに把握できる。
- 10件から目的の計測を迷わず見つけられる。並べ替え後も保存・再読込で順序を維持する。
- タップ領域44px、キーボード操作、読み上げラベルを維持する。
- ライト／ダーク／端末に合わせるを切り替え、再読込・PWA再起動後も選択を維持する。
- 計測中のテーマ変更、再読込、オフライン起動で時間が失われない。
- 既存10テストとPlaywrightのブラウザテストが成功する。
