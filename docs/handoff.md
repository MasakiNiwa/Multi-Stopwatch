### 直した問題

- 追加してからキャンセルすると空の計測が残った。追加は下書きを編集画面で確定してから保存する方式に変更
- 操作のたびに全カードを作り直していたため、フォーカス・スクロール位置が失われた。id単位の差分更新に変更
- 計測中のカードで編集画面を開くと、累積値（表示より短い時間）が出ていた。表示中の時間を初期値にし、**変更した時だけ**反映する
- 経過時間の修正が「秒だけの入力」だった。時/分/秒に分割
- 経過時間を0に戻せないリセットボタンが押せる状態だった。0のときは無効化
- 読めない保存データのとき、案内文が指す「バックアップを保存」が閉じた折りたたみの中にあった。自動で開く
- `confirm()`による確認を、アプリ内ダイアログへ変更（インストール後の表示差とデザイン統一のため）

### UI/UXの変更

- スマホ前提の1カラム。カードは「名前 → 状態 → 時間 → 目標 → 操作」の順で、開始/停止を最大の操作にした
- 旧Flutter版の時間表示（`00h00m00s`の単位付き）を引き継ぎ、秒を控えめにして時・分を読み取りやすくした
- 計測中のカードは枠線・淡い色・点滅ドットで区別。合計と計測中の件数は上部に固定表示
- 色選択をセレクトボックスから見本付きの選択肢へ。並べ替えはカード右上、破壊的操作は下段に分離
- 空状態、削除・リセット・復元の確認、操作結果の通知（8秒で消える）を追加
- ダークテーマ、`prefers-reduced-motion`、44px以上のタップ領域、全操作のキーボード対応とラベル付け

### 構造

- `public/src/ui.js` を追加し、描画とダイアログをapp.jsから分離（app.jsは状態・保存・イベントのみ）
- `model.js` に `setElapsed` `total` `running` `parts` `speak` `progress` を追加。表示と集計も純粋関数側でテストできる
- `sw.js` はVERSIONをv0.2.0へ。ui.jsを事前キャッシュに追加し、範囲内の未知パスは本体へフォールバック
- HTML/CSSは1行圧縮をやめて改行した。差分レビューと今後の調整のため。圧縮が望ましければ戻す

### 判断が要る点（ChatGPTに見てほしい）

1. **長い名前・メモの切り詰め**（3行/4行）。全文はカードに出ないが`title`と編集画面で読める。この割り切りでよいか
2. **削除ボタンをカード上に常設**した。誤操作は確認ダイアログで防いでいるが、編集画面へ隠す案もある
3. **HTML/CSSの整形**（上記）。初期基盤の書式と方針が違うため、リポジトリの方針として決めてほしい
4. **色は4色のまま**にした。旧版は8色だが、schema v1の`COLORS`を変えずに済ませている。増やすなら移行の要否を含めて次段階で
5. **平均時間・固定7タブ・履歴は未着手**。design.mdの拡張順序どおり、初版の範囲を広げないため見送った

## v0.4 コンパクト一覧とテーマ選択（2026-09-13 / Claude）

次の担当：**ChatGPT（ディレクター兼レビュアー）**。Issue #4 の実装です。

### 一覧の作り直し

カード型（1件297px、390×844で完全に見えるのは1件）を、1件1行のコンパクト表示に置き換えた。
1行66px。**390×844で4件なら4件すべて、10件でも6件が固定ツールバーの上に収まる**。10件の総高さは2397px→1270px。

行の構成は左から、並べ替えハンドル、開始/停止、名前＋状態、右端に時間。2行目は行幅いっぱいを使い、目標の残り％かメモを表示する。
旧Flutter版と同じく「時間と名前が一行に並ぶ」形に戻し、単位付き表示（`00h00m00s`）は継承した。

**通常表示との切替は作らず、常時コンパクトにした。** 切替は設定と説明が増える割に、隠れた情報（メモ・目標の正確な値・低頻度操作）は
詳細画面ですべて読めるため。実画面で比較した結果、切替の必要性を感じなかった。必要なら「ゆったり表示」を後から足せる。

### 目的の計測を見つける・並べ替える

- **絞り込み**：6件以上で名前・メモの検索欄を出す。全角半角と大文字小文字を無視して一致（`matches`）。「10件中1件を表示」と件数を出す
- **並べ替え**：行左端のハンドルをドラッグ（マウス・タッチ共通のPointer Events、画面端では自動スクロール）。
  同じハンドルにフォーカスして**上下キー**でも移動でき、押しっぱなしでも連続で動く。詳細画面にも「↑上へ移動／↓下へ移動」を置いた
- 絞り込み中はハンドルを無効化する。隠れている行との前後関係が決められないため。理由をtitleに出している
- 並べ替えは操作直後に保存し、再読込後も維持する

### 低頻度操作の整理

編集・リセット・削除・並べ替えを行から外し、名前部分を押して開く**詳細画面**に集約した。行に残したのは開始/停止とハンドルだけ。
詳細画面は計測中も時間が動き、閲覧専用のウィンドウでは中身を読めるが操作ボタンは無効になる。

### テーマ選択

- ヘッダーに「端末／ライト／ダーク」の3択。初期値はsystem
- 保存は `multi-stopwatch:prefs:v1`。**計測データのschema v1には触れていない**。設定が壊れていても既定値へ戻すだけで、計測データには影響しない
- `index.html` の先頭で保存値を読んで `data-theme` を確定させ、初回描画のちらつきを防ぐ。この属性は常に light か dark のどちらかになるので、CSSのダーク定義は1か所で済む
- `<meta name="theme-color">` はJSが1つだけ管理し、選択テーマに追従する。manifestの `theme_color` / `background_color` はライト側の色に揃えた（standaloneの起動画面は静的なため）
- 端末設定に追従するモードでは、OSのライト/ダーク変更に即座に追従する

### 検証

`npm test` 15件成功（既存10件＋並べ替え・絞り込み・短縮表記・設定保存の5件）。
`npm run test:browser` を拡張し、一覧の密度・44pxのタップ領域・絞り込み・キーボード並べ替えと保存・テーマ保存・オフライン起動・詳細画面をCIで検査する。
実ブラウザでの結果は docs/acceptance.md に追記した。

### 実装中に見つけて直した問題

- 上下キーを速く2回押すと2回目が効かなかった。行を動かすとフォーカスが外れるため。`sync`でフォーカスを復元するようにした
- 詳細画面が開いた直後は空で、最大250ms後の更新まで中身が出なかった（フォーカス先のボタンにラベルが無い状態だった）
- 閲覧専用のウィンドウで詳細ボタンが押せるのに何も起きなかった。閲覧は許可し、中の操作だけ無効にした

### 判断が要る点（ChatGPTに見てほしい）

1. **常時コンパクト**の是非。「ゆったり表示」を選べるようにするか
2. **開始/停止を丸いアイコンボタンにした**こと。文字ラベルは状態表示（計測中／停止中）と詳細画面の「▶ 開始」で補っている
3. **行の名前は1行で切り詰め**。全文は`title`と詳細画面。390pxで日本語10文字強まで
4. **PC表示を760px幅の1カラム**にした。並べ替えのある一覧は多段組みと相性が悪いため。v0.3は1120pxの多段組みだった
5. **絞り込み中は並べ替え不可**。この割り切りでよいか
