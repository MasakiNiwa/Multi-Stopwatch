# 設計と旧版の棚卸し

## 目的

「やるべきことを始めて、続けられる」を助ける。開始への手数を減らし、積み重ねが見える。自分で使って不便を見つけ、直せる構造にする。達成表示で小さく報いるが、連続記録の途切れや未達を責めない。

## 構造

### v0.7 / schema v3（最新。v0.8でも変更なし）

`{ version: 3, timers: [...], groups: [...] }`。配列名は既存の `timers` を維持し、各要素の `kind: 'timer' | 'set'` で区別する。Issue #8の `items` への改名案から変更した。既存の保存・順序・UIの接続を保つため。

- timer: 従来のフィールド＋`kind: 'timer'`, `parentId: null | setId`
- set: `id, kind: 'set', parentId: null, name, memo, color, targetMs, groupId, lastChildId`
- setにelapsedMs/startedAtを保存しない。`viewItem` の表示専用投影がaggregateMsと稼働状態を計算し、投影の保存はvalidationで拒否する
- v1/v2の既存timerはすべて単独timerへ移行し、時間・順序・稼働時刻・groupIdを維持する。v3を出力し、v1/v2/v3を復元可能
- 同じ親の子は最大1件稼働。切替・稼働中の所属変更は同じnowで停止／開始し、一度の保存で反映する
- 子のgroupIdは親に従う。親のグループ変更は全子へ適用し、単独化ではグループを保持する
- 全体とランキングはtimerだけ。set小計を再加算しない。各timerは10年上限、set小計は子の合計のため10年では切り捨てない
- 順序は配列内の兄弟の相対順。描画時に親→子へまとめる。一括sort・上下キー・ドラッグは兄弟内のみ。所属変更は編集画面で行う
- 親は初期折りたたみ。検索時には一致する子の親も表示する。親操作の履歴がなければ子選択を促す
- 削除モードはセッション内のみ。直接削除後はメモリ上の直前stateから1回取り消せる。次の記録変更／外部storageイベント／再読込で無効になる。保存失敗では元stateと取り消しを維持する
- セットの既定削除は子を単独化。全削除は別の確認付き操作。親のリセットは初版では提供しない

以下は旧版からの設計経緯。保存版の現行契約は上記v3を優先する。

ビルド不要のES Modules。public/src/model.jsは純粋関数で時刻を引数に受け取る。storage.jsはschema v1の保存契約、app.jsはイベント・状態、ui.jsは描画とダイアログ、style.cssはデザイン変数。PWA登録・import/exportは現状app.jsに置き、必要になった段階で分割する。汎用プラグイン基盤を先回りで作らない。

app.jsとui.jsの分割は、初版UIの実装でDOM操作が状態管理を上回った段階で行った（2026-09-13 / Claude）。ui.jsはアプリの状態を持たず、渡された配列を描画するだけにして、計測ロジックとの境界を保つ。

v0.5で `stats.js`（集計）と `sorting.js`（一括並べ替え）を追加した。どちらもDOMを触らず、stateと現在時刻だけを受け取る純粋関数。表示から切り離してあるので、集計や並び順の仕様はNodeのテストで固定できる。外部ライブラリは追加していない。この規模では依存を足してもオフライン配信・GitHub Pages・更新の安全性が改善しないため。

並べ替えの仕様（`sorting.js`）：全11条件。同値のときは適用前の順序を保つ安定sort。名前は `Intl.Collator('ja',{numeric:true,sensitivity:'base'})` で、かなは漢字より前、`項目2` は `項目10` より前、`ん` と `ン` は同値になる。**未分類はグループ名順の最後**、**目標なしは進捗順の昇順・降順とも最後**に置く。絞り込み中でも表示中だけでなく全件へ適用する。

集計の仕様（`stats.js`）：各タイマーが現在持つ累計を合計する。稼働中は現在値を含む。割合はすべて同じ全体合計で割るため、0件でも全部0秒でもNaNやInfinityにならず0になる。定義済みのグループは0件でも一覧に残し、未分類は所属がある時だけ出す。ランキングの同着は同順位で、次の順位は席次分だけ飛ぶ。

状態（schema v2）：`{version:2,timers:[{id,name,memo,color,elapsedMs,startedAt,targetMs,groupId}],groups:[{id,name}]}`。
`groupId` は `null`（未分類）か、`groups` に実在するidのどちらか。存在しないidを指す記録は `validate` が拒否する。
保存キーは `multi-stopwatch:state:v1` のまま。キーは記録の名前であって、schemaの版は値の中の `version` が持つ。キーを変えると既存の記録が孤立するため変えない。

表示設定は別キー `multi-stopwatch:prefs:v1` に `{version:1,theme:'system'|'light'|'dark'}` で保存する。計測データとは寿命も壊れ方も違うため、schemaを分けて相互に影響させない。設定が読めないときは既定値へ戻すだけにし、計測データのように閲覧専用へ落とさない。

### v1→v2の移行（2026-09-13 / v0.5）

`migrate` は純粋関数で、v1の各タイマーに `groupId: null` を足し、`groups: []` を付けるだけ。時間・稼働状態・順序・名前・目標をそのまま持ち越す。
読み込み時に移行するが、**その場では書き戻さない**。次に何か保存した時点でv2として書かれる。読むだけで記録を書き換えないほうが、閲覧専用の画面や事故時の復旧に都合がよい。
未知の版（v3以降）や壊れた値は今までどおり例外にして閲覧専用へ落とす。黙って初期化や上書きはしない。
バックアップの書き出しはv2。読み込みはv1/v2の両方を受け付け、v1なら移行してから取り込む。
動作中の経過時間 = 保存済み累積 + max(0,現在時刻 − 開始時刻)。停止で累積へ確定しstartedAtをnullにする。リセットは停止して0に戻す。目標を超えても計測継続。

現在はDate.now方式。スリープやプロセス終了を挟んだ復元に強いが、時計変更で増減する。将来、単調時計併用と時計異常検知を検討する際も、停止期間・OSスリープ・再起動の契約を先に決める。

永続化は操作単位で検証→保存→画面反映。毎描画の書込みはしない。保存失敗時は状態を更新しない。読めないデータは閲覧専用にして元データの書き出しを可能にする。Web Locksで単一書込み画面を確保し、別画面はstorageイベントで更新する。

### 配色（2026-09-13 / v0.5レビュー反映）

Material 3の考え方に寄せたsemantic tokenで組む。外部UIフレームワークは入れない。この規模の静的PWAでは、依存を足してもオフライン配信・GitHub Pages・更新の安全性が改善しないため、CSS変数で同じ構造を作る。

- `--primary` / `--on-primary` / `--primary-container` / `--secondary-container` / `--surface` と5段の `--surface-container-*` / `--on-surface` / `--on-surface-variant` / `--outline` / `--outline-variant` / `--error`
- primaryは低彩度の青紫1系統だけ。主要ボタン、計測中のトグル、統計の棒はすべてこれを使う
- タイマーの4色は「どの計測か」と「計測中かどうか」の識別に限る。左端の帯、枠線、状態ラベル、進捗バーだけに出す
- ダークの背景は紺ではなくニュートラルグレー。奥行きはgradientやshadowではなく、surface containerの段差とoutlineで作る
- gradient・glow・radial背景・強い影は使わない。影はダイアログのみ
- 計測中は「塗りつぶしトグル」「計測中の文字」「動くドット」「枠線」で示し、色だけに頼らない
- light/darkとも本文・ラベル・ボタンのコントラストは4.5:1以上（実測で最小6.6:1）

### 数字入力（同上）

- 数値欄はfocusで全選択し、そのまま打ち替えられる。タップ後にキャレットが置かれる端末向けに、focus直後とフレーム後の2回選択する
- 目標には「なし / 15分 / 30分 / 1時間 / 2時間」のプリセットを置く。押すと時間・分に反映し、その後の手入力で微調整できる（手入力するとプリセットの選択表示は外れる）
- 「経過時間の修正」は既定で折りたたみ、要約に現在値を出す。通常の編集では触れずに済ませる
- 空欄は入力途中として許容し、保存時に0として扱う。消した瞬間にエラーにしない
- `inputmode="numeric"` と `enterkeyhint` を付け、ソフトキーボードから次の欄へ進みやすくする

### 統計の更新（同上）

統計は差分更新にする。行をキーで使い回し、変わった文字とバー幅だけを書き換える。100件でも毎回作り直さない。
再集計の間引きは `statsTick`（純粋関数）が判定する。判定に使う「秒」は壁時計ではなく**これから表示する累計の秒**にする。累計は稼働中のタイマー数だけ速く進むため、壁時計で1Hzに固定するとヒーローの合計と統計パネルの合計が最大1秒ずれて見える。記録が変わったとき、タブや画面向きが変わったときは即時に再計算する。

レイアウトは自動で切り替える。`(orientation: landscape) and (min-width: 800px)` を満たす画面は計測一覧と統計の2カラム、それ以外はタブ。タブはARIAのtablistで、2カラムのときはタブを隠して両方をregionにする。`auto/tab/panel` の手動設定はissueで任意とされていたため入れていない。設定を増やす前に自動切替の不満を実使用で見たい。
高さの低い横画面（`max-height: 560px`）ではヘッダーを縮め、2カラムのときはヒーローの合計表示を隠す。統計パネルに同じ数字が出ているため重複であり、その分を一覧に回せる。

### ブランドアイコン（2026-09-13 / v0.6）

`public/icons/icon.svg` と `icon-maskable.svg` が原本。PNGはここから必要な解像度へ書き出す（`scripts/` には置かず、生成手順をこの文書に残す）。画像生成は使わない。形を数値で決められるSVGで描く。

- 図形はv0.5のタイトル左にあった「円環＋右上の点」を正とする。一般的なストップウォッチ形へ置き換えず、このツール固有のミニマルな意匠を残す
- `icon.svg` は40pxのCSS版を64pxへ正確に拡大した形。配色はライトテーマのブランドペア（`#dde1f9` ＋ `#323c6b`）で固定する
- `icon.svg` は角丸バッジで外側が透過。faviconとmanifestの `purpose: any` に使う
- `icon-maskable.svg` は同じ形と配色で背景を全面塗りにし、図形を中心から半径40%の安全領域に収める
- Apple touch iconは透過に弱いため、マスカブル側の全面塗りから生成する
- ヘッダーはv0.5のCSS版を維持し、明示的に選んだライト/ダークテーマへ追従させる。SVG原本は同じ寸法比を使う
- manifestが参照するPNGは `-v6` 付きのファイル名にした。インストール済み端末が古いアイコンをキャッシュしていても、名前が変われば取り直される（ただしOS側のキャッシュで即時とは限らない。READMEに明記）

### ヘッダーの操作（同上）

テーマは3分割のラジオをやめ、44pxのアイコンボタン1つにした。押すと今見えているテーマの反対へ切り替え、その選択を保存する。
表示するアイコンは**押した結果**（ライト表示中は月、ダーク表示中は太陽）。`aria-label` と `title` も「ダークテーマに切り替える」「ライトテーマに切り替える」と切り替わり、切替時はライブリージョンで通知する。
保存設定がない初回は端末設定に従い、端末設定が変わる間も追従する。明示的に押した時点で `system` から `light`/`dark` へ確定する。prefsのschema（`system|light|dark`）は変更していない。

ヘルプは同じ並びのアイコンボタンからダイアログで開く。基本操作・グループ/並べ替え/統計・インストール/オフライン・データの4見出しで、バックアップと復元の操作もこの中に集約した。ページ末尾の折りたたみは廃止して導線を1つにした。
保存データが読めないときはヘルプを自動で開く。復旧の説明と「バックアップを保存」へ確実に届かせるため。ヘッダーには将来の設定ボタンを足せる余白を残してあるが、空のボタンは置かない。

### 親子UI（2026-09-13 / v0.8 / Claude）

v0.7のセット行は名前・時間・注記を3段に積み、専用の展開ボタンを右端に持っていた。10セットを折りたたんだ状態で390×844に入る行は4行、セット行の高さは82px（通常行64px）だった。行密度を犠牲にしないという条件に対して、セットだけが1.3倍の面積を使い、かつ通常行と操作数も見た目も違っていた。

v0.8はセット行を通常行と同じ2段・同じ操作数にした。結果は下表（Chromium 141、折りたたみ、seedは10セット50計測＋単独10件）。

| | v0.7 | v0.8 |
| --- | --- | --- |
| セット行の高さ | 82px | 64px（通常行と同一） |
| 表示行数 320×844 | 3 | 5 |
| 表示行数 390×844 | 4 | 5 |
| 表示行数 1280×900 | 5 | 6 |
| 横スクロール | なし | なし |

- 展開の三角は専用ボタンをやめ、名前の行頭へ `⌄` / `⌃` として入れた。行全体（`[data-action="open"]`）が展開トグルで、`aria-expanded` と「〇〇の子3件を表示する」ラベルを持つ。**通常行の「行＝詳細シート」と意味が変わる点は、行頭マーカー・`セット`チップ・子のインデントの3つで示す**
- 名前の `セット · ` 接頭辞をやめ、メタ行の `セット` チップに移した。接頭辞は長い日本語名の先頭6文字分を奪い、省略が早く始まっていた
- セットの時間には `計` を前置し、自分の計測ではなく子の合計であることを数字の位置で示す
- セット行は状態チップ（点＋「計測中」）を隠し、注記に `計測中 問題演習` / `前回 復習` / `子 3件` / `子がありません` と言葉で書く。稼働の識別は枠線・塗りつぶしトグル・この文言の3系統で保つ（色のみに依存しない方針は維持）
- 子は左罫をセット色の `color-mix` にし、幅を2px→3pxへ。折りたたみ／展開の境目が視線で追えるようにした

名称「セット」は変えなかった。「グループ」は既に別概念（分類）に使っており、「プロジェクト」「まとまり」はどちらも意味が広い。名前を変える代わりに、行に `セット` チップと `計` を出して**語ではなく画面で意味を示す**方針にした。名称変更はヘルプ・issue・既存文書の語彙を一斉に触るため、実機の声が出てからにする。

### 整理操作の導線（同上）

「親の展開」と「親の詳細」は同じ行に同居させられない。次の3案を比較した。

| 案 | 内容 | 判断 |
| --- | --- | --- |
| A（採用） | 行全体＝展開。展開した親カードの中に `＋ 子を追加` `編集・削除` を置く | 操作が親の直下にまとまり、子の件数に関係なく位置が一定。折りたたみ中は0pxで密度に影響しない |
| B | 操作行を子の末尾に置く | 5件を超えると親から遠く、スクロールしないと見えない。v0.7の配置（親の中）を変える理由にならない |
| C | 行を長押し／右スワイプで詳細 | 発見できない。キーボードと支援技術に等価な導線を別途作る必要があり、実装量に対して得るものが少ない |

- 採用したAで、v0.7の `セットの編集・操作` は `編集・削除` に縮めた。「操作」は開始/停止と紛らわしく、実際に開くシートの中身は編集・移動・削除である
- `＋ セット` と `削除モード` は一覧上部の独立した行を占めていた。並べ替え・グループと同じ `.tools-row` へ寄せ、ツール行を2行から1行へ減らした
- **セット作成の直後はフォーカスを `＋ 子を追加` に置く**。新しいセットは必ず空で、次の操作は最初の子の追加に決まっている。作成→子追加が保存ボタンからの1操作になる
- **単独化（セットから出す）は詳細シートの1タップにした**。v0.7は編集画面の所属セレクトのみ。押すと所属だけを外し、グループはそのまま残す（`editItem(state, id, {}, null, now)` で稼働中でも同じnowで整合を取る）。シートの1行目に `セット：資格勉強／グループ：学習` を出し、今どこに属しているかを操作の前に示す
- 子の移動（別セットへ）は編集画面の所属セレクトのままにした。移動先の選択が必要な操作で、シートに20個のセットを並べても短くならない

### 削除とUndo（同上）

- 削除モードで連続削除するとき、フォーカスを毎回ツールバーへ返さない。削除した行の**次の行の削除ボタン**へ移す（最後の行なら手前の行）。キーボードとスイッチ操作で「削除→Tabで戻る」の往復が消える
- Undoバーの文言を `「○○」を削除（子は残しました）。次の操作まで取り消せます` にした。有効期間は時間ではなく次の記録変更までであり、それを提示の場で伝える。読み上げ（live region）にも同じ内容を出す
- Undo実行後はフォーカスを削除モードの継続に合わせて `削除モード` または `＋ 新しい計測` へ戻す。取り消した行は消えていないので、行へ戻す必要がない
- 複数選択削除は入れていない。実機需要を確認してからという指示に従った

### 統計のセット内訳（同上）

- v0.7のセット小計は子を `テキスト 02h06m00s / 問題演習 04h11m35s / …` と1行に連結していた。子が4件を超えると1行に収まらず、割合も読めない。v0.8は**親1行＋子の上位3行＋「ほか○件」**に分けて表示する
- 子の割合は全体ではなく**そのセット内**の割合にした。内訳だけで100%になり、セット内の偏りが読める（全体比は親行の割合が担う）
- 並びは親＝合計の降順、子＝そのセット内の降順。上位3件は「そのセットで何に時間を使ったか」に直接答える
- 見出しを `グループ別（計測の分類）` と `セット別小計（親子の内訳）` にし、セット別小計をグループ別の直後、ランキングの前へ移した。似た棒グラフが3つ並ぶため、性質の近い2つを隣接させ、補助語で役割の違いを書く
- ランキングは従来どおりtimerのみで、親を混ぜない。全体合計・グループ別もtimerのみを数え、セット小計を再加算しない（二重計上禁止は単体テストで維持）

### 親子ドメイン関数の分離（同上）

`sets.js` への分離は今回見送った。`toggleItem` `editItem` `removeItem` はtimerとsetの両方を扱う1つのライフサイクルであり、切り出すと `elapsed` `start` `stop` `total` を双方向に参照する。model.jsは226行で、親子部分は末尾70行にまとまっている。分離するなら「timerのライフサイクル」と「集計・表示投影」の軸で切るほうが素直で、履歴schema（将来）を入れる回に合わせたい。

PWAは同一バージョンのアプリ一式を事前キャッシュ。更新は待機し、全画面を閉じた後に切替。scopeを含むキャッシュ名で他のPagesアプリを巻き込まない。外部フォント・CDNなし。
